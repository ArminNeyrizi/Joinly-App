# AI Project Overview & Architecture Guide

## 🚀 خلاصه پروژه
پروژه **Joinly** یک سیستم ماژولار و پیشرفته برای مدیریت، بررسی و ثبت‌نام دانشجویان در آکادمی‌های تخصصی (DevOps، مهندسی نرم‌افزار، طراحی و...) است. این سیستم بر پایه معماری Layered Module طراحی شده است.

---

## 🛠️ پشته فنی (Tech Stack)
- **Framework:** Next.js (App Router - React Server Components by default)
- **Language:** TypeScript (Strict Type Checking)
- **Database & ORM:** PostgreSQL + Prisma (Custom Generated Path)
- **Authentication:** Supabase Auth (Server & Client integration)
- **Styling:** Tailwind CSS + Shadcn UI (RTL Support)

---

## 📁 ساختار معماری و لایه‌بندی کدها (Architecture & Directory Rules)

کدهای اصلی برنامه در مسیر `src/modules/` قرار دارند. هر قابلیت سیستم (مثل ادمین، احراز هویت، ثبت‌نام) یک ماژول مستقل است. هوش مصنوعی باید دقیقاً از لایه‌بندی زیر پیروی کند و نباید لایه‌ها را با هم ترکیب کند:

### ۱. لایه مخزن داده (`repository.ts`)
- **وظیفه:** ارتباط مستقیم با دیتابیس از طریق Prisma.
- **قانون:** هیچ منطق بیزینسی، بررسی دسترسی یا ارور سطوح بالاتر نباید اینجا نوشته شود. فقط Queryهای دیتابیس.
- **مثال:** `prisma.enrollment.create(...)`

### ۲. لایه سرویس (`service.ts`)
- **وظیفه:** پیاده‌سازی منطق اصلی بیزینس (Business Logic)، اعتبارسنجی قوانین (Validation) و بررسی سطوح دسترسی (مانند `requireAdmin`).
- **قانون:** این لایه توابع لایه Repository را فراخوانی کرده و خروجی را پردازش می‌کند.

### ۳. لایه اکشن‌ها (`actions.ts`)
- **وظیفه:** پل ارتباطی بین فرانت‌اند و بک‌آند با استفاده از Next.js Server Actions.
- **قانون:** تمام اکشن‌ها باید حاوی `'use server'` باشند. این لایه فقط `service.ts` را فراخوانی می‌کند و خطاها را برای نمایش در UI مدیریت می‌کند.

### ۴. لایه کامپوننت‌ها (`components/` & `src/app/`)
- **وظیفه:** نمایش رابط کاربری (UI).
- **قانون:** کامپوننت‌ها داده‌ها را از Server Actions یا مستقیماً از کامپوننت‌های سروری دریافت می‌کنند و به کاربر نمایش می‌دهند.

## ⚠️ نکات بسیار حیاتی برای هوش مصنوعی (Critical Constraints)

1. **مسیر سفارشی کلاینت پریسما:** 
   پریسما در این پروژه دیتای خود را در پوشه پیش‌فرض node_modules نمی‌سازد. کلاینت پریسما دقیقاً باید از مسیر زیر Import شود:
   `import { PrismaClient } from "@/generated/prisma/client";`
   و برای دیتابیس از نمونه متمرکز در `@/lib/db` استفاده شود.

2. **زبان و ظاهر سیستم:**
   - تمام متون فرانت‌اند، دکمه‌ها، پیام‌های خطا و لاگ‌های سمت کاربر باید **کاملاً فارسی، روان و راست‌چین (RTL)** باشند.
   - نام متغیرها، متدها، جداول دیتابیس و کامپوننت‌ها در کدنویسی باید **کاملاً انگلیسی** باشند.
   - فونت اصلی پروژه **Kalameh** است.

3. **وضعیت‌های ثبت نام (Enrollment Statuses):**
   وضعیت قدیمی `CONFIRMED` کاملاً از سیستم حذف شده است. وضعیت‌های مجاز و معتبر سیستم برای ثبت‌نام‌ها فقط شامل موارد زیر است:
   - `PENDING` (در انتظار بررسی اولیه)
   - `HOLD` (قرارگرفته در لیست رزرو/انتظار توسط ادمین)
   - `APPROVED` (تایید نهایی ثبت‌نام)
   - `REJECTED` (رد شده به همراه ثبت `rejectReason`)

4. **مدیریت ظرفیت‌ها:**
   تغییر وضعیت ثبت‌نام‌ها اثر مستقیم روی ظرفیت کلاس‌ها (`enrolledCount` در `CourseSection`) دارد که باید حتماً به صورت یک تراکنش دیتابیسی (`$transaction`) در لایه کامپوننت‌های دیتابیس اعمال شود.
